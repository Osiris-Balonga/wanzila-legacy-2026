# #64 — Fidélité du dashboard analytique

Référence : [admin-dashboard.png](../../mockups/admin-dashboard.png) et son [manifest](../../reference-manifest.json). Captures Playwright de l’implémentation : [390 px](dashboard-activity-390.png) · [1440 px](dashboard-activity-1440.png) · vérifications complémentaires [320 px](dashboard-activity-320.png) et [768 px](dashboard-activity-768.png).

La [capture 1440 avec tuiles OpenFreeMap chargées](dashboard-activity-live-map-1440.png) est distincte des captures déterministes ci-dessus. Le test réseau optionnel attend que MapLibre annonce `ready` et qu’au moins une tuile vectorielle `.pbf` réponde avec succès. Les autres captures substituent seulement le fond cartographique pour rendre la comparaison géométrique stable ; les réponses API sont des fixtures conformes à #54 et #63, pas des chiffres codés dans le composant.

Si les comptes courants #54 et #63 diffèrent pendant un rafraîchissement, le dashboard affiche une note avec les deux instants `asOf` ; les KPI/deltas restent attachés à #63 et les séries/tunnel à #54. Une simple différence de quelques millisecondes sans divergence de comptes ne déclenche pas la note.

Les tests Playwright couvrent requêtes authentifiées, 7d/30d, parse Zod, loading/empty/401/403/500 et JSON invalide, pagination au-delà des vingt premiers points, six deltas, cohérence des instantanés, navigation clavier, focus, absence de débordement à 320/390/768/1440 px et absence de requête #63 sur `/admin/qualite`. À 320/390 px, le tunnel garde ses six barres horizontales lisibles.
